## [0.6.0] — 2026-10-14

Главное: **починен gateway** — сессия больше не падает после READY
(шторм подписок по всем гильдиям и жёсткий разбор GUILD_CREATE убиты),
добавлен **модуль проверки обновлений** по GitHub Releases, файловые
логи для диагностики, и закрыт большой пласт «полного клиента»:
вложения, эмбеды, стикеры, ответы, закреплённые, поиск по каналу,
смена статуса и расширенные профили.

### Fixed
- **Стабильность gateway (главный фикс релиза)**: после READY клиент
  рассылал op 37 по ВСЕМ гильдиям сразу + op 14 на каждую гильдию —
  по этому шторму пакетов сессия обрывалась («Соединение потеряно…
  пробуем снова с backoff»). Теперь подписки точечные: op 37 + op 14
  уходят только при открытии конкретного сервера (`subscribe_guild`),
  с дедупом на повторные входы.
- **Жёсткий разбор GUILD_CREATE убран**: одна «кривая» гильдия больше
  не роняет всю сессию (`?` на serde-ошибке → reconnect-цикл). Разбор
  мягкий: warn в лог, сырой payload — в UI.
- **Версия протокола юзер-сессий → v9** (как официальный веб-клиент и
  все self-hosted реализации; v10 остаётся ботам), `presence.status`
  в IDENTIFY — `unknown`/`since: 0` — в точности как у рабочего
  референса. RESUME идёт на той же версии, что и IDENTIFY.
- **«?»-аватары в списке ЛС**: юзер-READY присылает `private_channels`
  с `recipient_ids` (без полных объектов) и отдельный массив `users`.
  Стор теперь гидратирует участников ЛС из этого справочника — имена и
  аватары на месте.
- Причина обрыва (close-код + reason) видна в жёлтом баннере и в
  настройках — больше не нужно гадать, почему отвалилось.

### Added
- **Проверка обновлений при старте**: `updater.rs` спрашивает
  GitHub Releases (`/releases/latest`), сравнивает semver и показывает
  плашку «Доступна версия X.Y.Z» со ссылкой на релиз (открывается во
  внешнем браузере через tauri-plugin-opener). Никаких автозагрузок —
  решение всегда за пользователем.
- **Файловые логи** (tracing-appender, суточная ротация в app_log_dir):
  релизная сборка без консоли теперь диагностируема — путь до лога
  показывается в настройках и копируется одной кнопкой для баг-репортов.
- **Вложения**: просмотр картинок (с лайтбоксом по клику), видео, аудио
  и файл-чипов с размером; загрузка своих файлов через нативный диалог
  (tauri-plugin-dialog) → multipart POST `files[N]` + `payload_json`
  (до 10 файлов, лимит 25 МБ без Nitro).
- **Эмбеды**: карточки ссылок с цветной полосой, автором, заголовком,
  описанием, полями, картинкой/превью и футером.
- **Стикеры**: PNG/APNG рендерятся с CDN, Lottie — аккуратной заглушкой.
- **Ответы**: кнопка «Ответить» в hover-действиях и контекст-меню,
  баннер над инпутом (Esc — отмена), превью родительского сообщения
  над ответом (из `referenced_message` или кэша канала).
- **Закреплённые сообщения**: кнопка 📌 в шапке канала открывает
  боковую панель со списком пинов и откреплением.
- **Поиск по каналу**: строка в шапке + панель результатов с переходом
  к найденному сообщению (GET /channels/{id}/messages/search).
- **Смена статуса**: клик по своему аватару в юзер-панели → меню
  В сети / Неактивен / Не беспокоить / Невидимка (PATCH
  /users/@me/settings), оптимистичное обновление точки.
- **Расширенные профили**: баннер, био, значок Nitro, общие сервера и
  количество общих друзей (GET /users/{id}/profile) в карточке профиля.
- Мини-иконка «закреплено» 📌 в шапке сообщения; пункт «Закрепить/
  Открепить» в контекст-меню.
- logic-test: +5 тестов сравнения версий (семвер-лайт из updater.rs), итого 23.

### Changed
- Мёртвый код вычищен: команда `get_dm_channels` (ЛС приходят через
  READY/get_state), `guildBannerUrl`, `dmColor`, `detectMode`,
  `ALL_UNICODE_EMOJI`, `ME_KEY`-хранилище, таблица intents в настройках,
  `DualWriter`, лишние `export` с внутренних типов. Снятые export
  (`TauriBackend`, `MentionResolver`, `EmojiCategory`, `DISCORD_EPOCH`)
  остаются доступными только внутри своих модулей.

## [0.5.0] — 2026-10-14

Три больших вещи: список серверов юзера наконец приезжает (правильный
IDENTIFY для пользовательских сессий), голос переведён на движок songbird
(современное шифрование вместо устаревшего xsalsa20_poly1305), реакции —
полноценные, с эмодзи-пикером и кастомными эмодзи сервера, а не только 👍.

### Fixed
- **Список серверов юзера**: пользовательские токены больше не шлют
  `intents` — как официальный клиент, IDENTIFY использует `capabilities`
  (53 607 934) + `client_state`. С интентами юзер-сессия получала
  урезанный поток и гильдии могли не приехать вовсе — теперь READY
  приходит полным. После READY клиент подписывается на события всех
  гильдий сразу (op 37 bulk subscribe), а списки участников берёт
  ленивыми диапазонами (op 14) вместо полного op 8 — ровно как
  официальный веб-клиент.
- **Браузерная личина обновлена до Chrome 149** (User-Agent и
  browser_version в X-Super-Properties синхронизированы) — по образцу
  discord-client-rs.

### Changed
- **Голосовой движок — songbird 0.6** (был: самописный стек на
  tokio-tungstenite + xsalsa20poly1305 + audiopus). Songbird ведёт весь
  сигналинг v4/v5 сам: рукопожатие, UDP IP discovery, NAT, шифрование
  (aead_aes256_gcm / xchacha20 — актуальные режимы Discord вместо
  устаревшего xsalsa20_poly1305, который сервера отключают), jitter-буфер
  приёма и opus-кодек. Удалено ~1 100 строк ручного кода
  (voice/ws, udp, crypto, codec, sender).
- Микрофон: cpal-колбек → MicTap → AsyncAdapterStream → RawAdapter →
  songbird Input (живой поток без известной длины, корректный EOF при
  завершении сессии).
- Приём: CoreEvent::VoiceTick → собственный микшер (прайминг/джиттер на
  дорожках) → cpal-вывод; speaking-кольца и уход участников — из
  SpeakingStateUpdate/ClientDisconnect songbird'а.
- Мьют/деафиен: эхо op4 обновляет songbird driver.mute вживую — движок
  шлёт тишину вместо микрофона, как официальный клиент.

### Added
- **Эмодзи-пикер реакций**: категории с заголовками и навигацией, поиск
  (по ключевым словам ru/en и именам серверных эмодзи), «Часто
  используемые» (localStorage, топ-24), секция кастомных эмодзи сервера
  (из GUILD_CREATE/GUILD_UPDATE), анимированные эмодзи (.gif).
- **Тоггл реакций**: клик по своей реакции снимает её (DELETE
  /reactions/{emoji}/@me), по чужой — ставит (PUT); поддержка
  MESSAGE_REACTION_REMOVE_ALL и MESSAGE_REACTION_REMOVE_EMOJI из
  gateway.
- **Кастомные эмодзи сервера** в реакциях и пикере (emojis из
  GUILD_CREATE кэшируются и отдаются в get_state), фолбэк :name:
  текстом, если CDN недоступен.
- Кэш гильдий: сохраняются кастомные эмодзи (GuildState.emojis).
- Демо-режим: кастомные эмодзи сервера, разнообразные живые реакции
  (🔥😂🦀💯🎉 вместо одного 👍).

### Compatibility
- Проверено: cargo clippy -D warnings (full + headless), fmt, logic-test
  18/18 (убраны тесты удалённых codec/crypto — их реализации больше не
  в приложении), svelte-check 0/0, vite build.

## [0.4.0] — 2026-10-14

Переделка клиентской части под пользователя: после входа юзер-аккаунтом
клиент больше не ведёт себя как бот. Главная страница ЛС — настоящая
страница «Друзья», списком друзей, заявками и блок-листом, а ЛС можно
начать первым (а не ждать, когда кто-то напишет «боту»).

### Fixed
- **READY больше не теряется по дороге в UI**: Rust-ядро теперь пробрасывает
  полный payload READY как dispatch — раньше `relationships` и
  `private_channels` не доходили до фронтенда вообще (список ЛС был пуст,
  даже если переписки существуют, а друзья не появлялись никогда).

### Added
- **Страница «Друзья» как в официальном клиенте**: табы Онлайн / Все /
  Ожидание / Заблокированные / Добавить в друзья; друзья с живыми статусами
  (онлайн/отошёл/не беспокоить + кастомный статус и игра в подписи).
- **Заявки в друзья**: отправка по имени пользователя (POST
  /users/@me/relationships), принятие/отклонение входящих (PUT/DELETE),
  отмена исходящих; человеческие сообщения об ошибках (лимит друзей,
  «уже отправлена», «уже друзья», rate limit).
- **Личные беседы по-настоящему**: кнопка «Написать» у друга создаёт DM
  через POST /users/@me/channels (команда `create_dm`) — юзер пишет первым,
  как в обычном клиенте; поиск сверху с выпадашкой «найти или начать беседу».
- **Блок-лист**: блокировка из списка друзей (PUT type:2) и разблокировка.
- **Вступление на сервер по приглашению**: кнопка «+» в рейле серверов —
  вставь ссылку discord.gg/… и заходи (POST /invites/{code}).
- **RELATIONSHIP_ADD / RELATIONSHIP_REMOVE**: друзья и заявки обновляются
  вживую из gateway; PRESENCE_UPDATE без guild_id обновляет статусы друзей.
- **REST-синхронизация друзей** (GET /users/@me/relationships) после входа —
  страховка от потерянного READY после RESUME.
- Демо-режим теперь показывает пользовательский аккаунт: друзья, входящая
  заявка, статусы, принятие заявки вживую.

### Changed
- **Лендинг после входа**: пользователь попадает на «Друзья», а не в первый
  сервер (авто-выбор гильдии остался только бот-аккаунтам/демо).
- Бот-аккаунтам честно показывается заметка «это бот-аккаунт» вместо
  замаскированной страницы друзей.
- Поиск в сайдбаре ЛС предлагает «Начать беседу» с друзьями, у которых
  ещё нет открытой переписки.
- get_state (hot-reload) отдаёт relationships и friend_presences.

## [0.3.1] — 2026-10-14

Хотфикс QR-входа: v0.3.0 реализовывала устаревшую (v1) схему remote-auth,
из-за чего QR-код вообще не генерировался — сервер закрывал соединение
после первого же шага рукопожатия.

### Fixed
- **QR-вход переписан на актуальный протокол v2** (по документации
  docs.discord.food и проверке против живого шлюза): ответ на `nonce_proof` —
  эхо расшифрованного nonce в base64URL без «=» (а не HMAC-proof);
  fingerprint приходит в `pending_remote_init` и сверяется с SHA-256
  собственного ключа (защита от подмены).
- **Обмен ticket → токен**: `pending_login` теперь приносит ticket, который
  обменивается на зашифрованный токен через `POST /users/@me/remote-auth/login`
  (раньше WebSocket ждал несуществующее поле `encrypted_token`).
- **Heartbeat по hello**: клиент сам шлёт `heartbeat` с интервалом из
  `hello.heartbeat_interval` и отслеживает `heartbeat_ack` (нет ACK —
  «зомби»-детект и обрыв).
- **Ошибки QR видны в UI**: любая ошибка сессии (сеть, таймаут, закрытие
  сервером с кодом) эмитится на фронтенд с текстом и кнопкой «Попробовать
  снова» — раньше она молча писалась только в лог.
- **Экран подтверждения**: при сканировании показывается, кто отсканировал
  QR (профиль из `pending_ticket`: `id:discriminator:avatar:username`).
- Стадия `connecting` со спиннером «Подключаемся к Discord…» вместо мигания
  плейсхолдера; Close-код 4003 корректно показывается как «QR истёк».
- Тесты logic-test обновлены под v2 (эхо-nonce, fingerprint, base64URL).

## [0.3.0] — 2026-10-13

Из бот-клиента — в полноценный клиент: вход своим аккаунтом (как Vesktop),
управление сервером и система плагинов в духе Vencord.

### Changed
- **Авторизация пользователя вместо bot-token**: QR-код (remote-auth v2:
  RSA-2048, OAEP-SHA256, HMAC-nonce-proof, зашифрованный токен), email+пароль
  (POST /auth/login) с двухфакторкой (TOTP), ручная вставка токена. Капча
  при email-входе честно детектится и предлагается QR.
- **Пользовательская сессия на всех слоях**: Authorization без префикса `Bot`,
  X-Super-Properties (base64-паспорт браузера), браузерный User-Agent,
  автоподтяжка client_build_number с discord.com, X-Context-Properties на
  логине, юзер-интенты (все 17 бит, включая «привилегированные» для ботов),
  presence в IDENTIFY. READY теперь разбирает private_channels — DM-список
  доступен сразу.

### Added
- **Управление сервером** (модалка по клику на имя сервера): имя (PATCH),
  каналы — создание/переименование/удаление с выбором типа и категории,
  роли — создание/удаление/цвет/hoist/41 флаг прав, участники — ник, роли,
  кик/бан, бан-лист с разбаном, инвайты — создание/отзыв.
- **Универсальный REST-прокси `api_request`**: любой метод/путь через
  Rust-слой с общими rate limits и заголовками — фундамент для UI и плагинов.
- **Плагины (Vencord-style)**: JS-объект-литералы в app_data/plugins,
  исполнение в WebView через `new Function` с sourceURL, события
  (message:create/update/delete/send, dispatch, ready, guild:*, voice:state),
  хук `message:send` (заменить/отменить отправку), REST-мост, CSS-инъекции
  с авто-чисткой, suppress-флаги (`typing`), изолированный storage, тосты.
  UI: вкладка «Плагины» в настройках (установка из кода, вкл/выкл, код,
  удаление). Примеры: silent-typing, message-logger.
- QR-SVG генерируется на Rust (crate `qrcode`, path-only, quiet zone 4).
- Демо-режим: симуляция QR-логина, мини-REST для настроек сервера,
  in-memory плагины — весь новый UI можно потрогать в браузере.

### Dependencies
- + rsa 0.9, sha2 0.10, hmac 0.12, base64 0.22, rand 0.8, qrcode 0.14

## [0.2.0] — 2026-10-13

Аудиодвижок: полный дуплекс — слышим собеседников и говорим сами.

### Added

**Приём звука (динамики)**
- Opus-декодирование входящих кадров: libopus 1.5 (через `audiopus`),
  моно-потоки апмиксятся в стерео — как у официального клиента.
- Jitter-буфер на SSRC-дорожках: переупорядочивание по seq, дедупликация,
  компенсация потерь (дыра ≤ 8 кадров — вставка тишины 20 мс, длиннее —
  ресинк без тишины), пре-ролл 40 мс на старт всплеска речи, потолок
  очереди 1 с.
- Микширование нескольких говорящих с жёстким клампом [-1; 1].
- Вывод через `cpal` (WASAPI / CoreAudio / ALSA), подбор конфигурации
  48 кГц F32 с фолбэком, линейный ресемплер для устройств с иной частотой,
  миксдаун/дабмикс каналов. Деафиен глушит вывод на уровне микшера.

**Передача звука (микрофон)**
- Захват микрофона через `cpal`: любой формат/частота → моно 48 кГц.
- Кодирование opus (режим Voip, 20 мс кадры), RTP-заголовок с
  seq/timestamp/marker, шифрование xsalsa20poly1305 (nonce = заголовок,
  tag-first), отправка через `try_send` без блокировки.
- Энергетический VAD с гистерезисом ~300 мс: op 5 SPEAKING отправляется
  только на переходах «заговорил/замолчал» — зелёные кольца у собеседников
  выглядят как при voice activity официального клиента.

**Управление**
- Мьют/деафиен гоняются прежним op 4; ядро теперь слушает эхо
  VOICE_STATE_UPDATE и на лету останавливает/возобновляет передачу и вывод
  без переподключения сессии.
- Сборка `--no-default-features` — headless-вариант без аудиоустройств:
  сигналинг, криптография и jitter работают, звук не выводится/не пишется.

**Инфраструктура**
- audiopus: на Linux линкуется системным libopus (libopus-dev в CI),
  на Windows/macOS собирает vendored-opus через cmake.
- CI: `CMAKE_POLICY_VERSION_MINIMUM=3.5` — vendored-opus несовместим с
  CMake >= 4 (совместимость с < 3.5 из CMake удалена); Linux не задет,
  там pkg-config.
- Тесты: 7 (jitter) + 3 (ресемплер) + opus roundtrip (steady state, 5 кадров)
  + RTP build/parse roundtrip; локальный logic-test — 16/16 с реальным
  libopus.

## [0.1.0] — 2026-10-13

Первый публичный выпуск.

### Added

**Ядро (Rust, src-tauri)**
- Gateway-клиент Discord (WebSocket): рукопожатие HELLO → IDENTIFY/RESUME,
  heartbeat ~41.25 с с детектом «зомби»-соединения по отсутствию HEARTBEAT_ACK,
  реконнект с экспоненциальным бэкоффом 1→30 с, обработка close-кодов
  (4004 — невалидный токен, 4014 — деградация интентов, 1000 — чистый реконнект).
- Кэш состояния: гильдии, каналы, участники, роли, сообщения, presence,
  voice states — за `RwLock` без блокировки UI-потока.
- REST-клиент с полными rate-limit-бакетами: парсинг `X-RateLimit-*` заголовков,
  маршрутные ключи с мажорными ID, 429-backoff, глобальный lock на `X-RateLimit-Global`.
- Голосовые каналы: полный сигналинг Voice v4 (WS HELLO → IDENTIFY → READY с SSRC →
  UDP IP discovery для NAT-проброса → SELECT_PROTOCOL → SESSION_DESCRIPTION),
  парсер RTP, шифрование xsalsa20poly1305 (nonce = RTP-заголовок, tag-first layout),
  маппинг SSRC → user через опкоды 12/13.
- Декодер Snowflake-ID (время создания, worker/process/increment) с тестами.
- 15 Tauri-команд: логин, гильдии/каналы/сообщения, голос, kick/ban, роли.
