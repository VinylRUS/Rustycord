# Changelog

Все заметные изменения RustyCord документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## [Unreleased]

### Added
- **Голосовой DSP: шумоподавление + автонастройка усиления (AGC)** —
  обработка микрофона в Rust-колбеке захвата, перед кодированием в Opus
  (`voice/dsp.rs`, чистый Rust без внешних крейтов):
  - шумоподавление — STFT (окно 1024, прыжок 512, окно Ханна, WOLA),
    оценка шума min-трекингом с заморозкой во время речи, винеровский
    гейн с over-subtraction и hangover (анти-«музыкальный шум»),
    временной гейт с гистерезисом VAD и рампой; три силы (слабое/
    среднее/сильное);
  - AGC — огибающая RMS речи ведёт усиление к цели −20 dBFS (быстро
    вверх до +30 dB, мягче вниз, в тишине заморожено — шум не
    разгоняется);
  - пер-сэмпловый лимитер (защита от клипа даже при выключенных
    обработках) и DC-блокер (~19 Гц — убирает смещение дешёвых
    микрофонов);
  - всё считается в реальном времени без аллокаций на стационарном
    пути: один FFT-1024 на 10.7 мс — единицы микросекунд.
- Настройки «Голос» (новая вкладка): тумблеры шумодава и AGC, выбор
  силы, применение на лету без перезахода в канал; живая телеметрия —
  уровни входа/выхода (dBFS), оценка шума, усиление AGC, сколько снял
  шумодав, индикатор речи; настройки персистятся в localStorage и
  восстанавливаются при старте.
- Индикатор уровня микрофона в шапке голосового канала (после
  обработки — ровно то, что уходит собеседникам), подсветка речи.

### Fixed
- **Шторм ошибок `GUILD_MEMBER_UPDATE: Cannot read properties of
  undefined (reading 'user')`** (525 в полевом логе за вечер) — Discord
  присылает поля участника прямо в payload (`d.user`, `d.nick`, …), а
  обработчики ждали обёртку `d.member`. Теперь ник/роли/аватары
  участников обновляются по-настоящему, а не роняют dispatch-цикл.
- Лимит gateway-команд 120/60 с: bulk-подписки чанкуются по весу
  (15 360 байт/кадр — как `updateGuildSubscriptions` официального
  клиента), при исчерпании слотов команды уходят в отложенную очередь
  без блокировки select-петли (пульсы и входящие кадры живут своей
  жизнью), подписки списков участников коалесятся по ключу
  «гильдия:канал» — шторм скролла больше не может приблизить close 4008.

### Planned
- Приём чужих трансляций: депакетизация H.264 (RTP) → MSE-рендер в webview.
- Передача видео-потока (камера/экран): захват + кодирование + транспорт.
- Сетка карточек форума (сейчас — список), теги постов.
- Отображение чужих аватаров-статусов в поповере реакций.

## [0.9.4] — 2026-10-16

Папки серверов наконец раскрываются по-настоящему (дубликаты id в
настройках протокола замораживали рендер), шлюз перестаёт молотить
IDENTIFY в петле 4002, а «последний кадр перед закрытием» теперь
виден в логе без всякого verbose.

### Fixed
- **«Папки не открываются — тёмные квадратики»** — в реальных
  `user_settings_proto` встречаются дубликаты guild id (прото допускает
  смешанный packed/unpacked повтор + мусор многолетних инкрементальных
  записей). Дубликат в keyed-each Svelte (`each_key_duplicate`) ронял
  DOM-обновление молча: клик по папке «не работал». Дедуп на трёх
  уровнях — декодер прото, нормализация в сторе, рендер. Гильдии,
  которых ещё нет в кэше (раскладка приезжает раньше стабов READY),
  больше не оставляют пустых дырок — плейсхолдеры в кружке папки и
  подсказка «серверы ещё грузятся…» в раскрытой.
- **Петля 4002** — три close 4002/4005 подряд теперь останавливают
  переподключения с человекочитаемой ошибкой (серия частых IDENTIFY
  на юзер-токене — антифрод-риск). Любая сессия, дожившая до READY,
  сбрасывает счётчик и backoff (раньше backoff застревал на 30 с
  навсегда после пяти обрывов).
- **`session.seq` не чистился** при INVALID_SESSION(false) и
  4002/4005/4007/4009 — свежий IDENTIFY до первого DISPATCH слал
  heartbeat со seq прошлой сессии.
- **4007/4009** падали в общую ветку и делали бессмысленный RESUME
  (неверный seq / истёкшая сессия не резюмятся) — теперь сразу чистый
  IDENTIFY, без лишнего круга через INVALID_SESSION.
- **SendText из консоли протокола** валидируется как JSON до отправки:
  мусор больше не убивает сессию 4002, ошибка видна тостом.
- Тост об обновлении больше не врёт про расположение плашки
  («рядом с профилем» → «внизу справа»).

### Added
- **Кольцевый буфер последних 10 исходящих кадров** (секреты
  `token`/`session_id` маскируются на любой глубине, пульсы op 1 не
  пишутся): при close 4002/4005 дамп уходит в лог одним блоком —
  «какой кадр сломал декодирование» восстанавливается без повторного
  воспроизведения. Строки: номер, возраст, метка команды, размер
  в байтах (после `serde_json::to_vec`, не оценка), JSON до 400 символов.
- **Токен-бакет 120 команд/60 с** (протокольный лимит шлюза, close 4008
  сверх него): при шторме подписок команды приостанавливаются до
  свободного слота — соединение сами не рвём. Ретраев и задержек «наугад»
  по-прежнему нет.
- DEV-хук `window.__app` в браузерной разработке — живой стор в консоли
  (в продакшен-сборке отсутствует).

## [0.9.3] — 2026-10-15

Догрузка участников при скролле (фикс «грузятся только первые 100»),
папки серверов раскрываются в рейле как в оригинале (вместо поповера
по центру экрана), защита сайдбара от мерцания между каналами.

### Fixed
- **«Грузятся только первые 100 участников»** — так и было задумано
  протоколом: стартовая подписка = один диапазон `[[0,99]]` (константа
  LD из бандла discord.com). Теперь сайдбар догружает сотни по мере
  скролла — математика 1:1 с `onScroll → GUILD_SUBSCRIPTIONS_CHANNEL`
  официального клиента: всегда `[0,99]` + сотни до видимой зоны +
  overscan в полвьюпорта, выравнивание границ по 100. Rust хранит
  подписанные диапазоны и переигрывает их после переподключения —
  докрученное скроллом не теряется. Под списком — «…и ещё N».
- **SYNC semantics**: применение SYNC сверено с бандлом —
  `sync(range, items)` это ПРИСВАИВАНИЕ `rows[start+i] = item` с
  удлинением списка, а не полная замена (v0.9.2 затирала хвост от
  `[100,199]` при повторном SYNC `[0,99]`). Удаления едут отдельными
  DELETE/INVALIDATE ops.
- **Мерцание сайдбара между каналами**: сервер держит подписки прежних
  каналов до LRU-вытеснения и продолжает слать их события. Теперь
  `subscribe_channel` фиксирует текущий канал СРАЗУ, снапшот и emit
  применяются только к нему, а события чужих каналов идут лишь в
  гидратацию кэша (пресенсы/карточки) — как UserStore/PresenceStore
  официала.
- **Папки серверов не открывались** — поповер по центру экрана был
  не по-дискордовски и путал. Теперь папка раскрывается прямо в рейле:
  цветной столбик с шапкой (имя папки) и серверами внутри; клик по
  серверу выбирает его, папка остаётся раскрытой; клик по шапке
  сворачивает — как в оригинале.

### Added
- **Демо-режим показывает папки и ленивый сайдбар**: два мини-сервера
  («Rust Playground», «Мемы про крабов») в папке «Проекты» + раскладка
  рейла, а `subscribeChannel` в моке эмитит `memberList` — контракт
  1:1 с продакшеном, ленивый список видно без входа в Discord.

### Verified
- `cargo check`/`clippy --all-targets -D warnings` (обычный + audio) —
  чисто; cargo fmt — ок; svelte-check — 0 ошибок; vite build — ок.
- Применение ops: 13 тестов в scripts/logic-test (SYNC-присваивание в
  пустой список, мульти-диапазонное дописывание, повторный SYNC без
  затирания хвоста, INSERT/UPDATE/DELETE индексы, INVALIDATE
  энд-инклюзив, полный цикл 100+2 строк) — PASS.
- Визуальная проверка демо (agent-browser + VLM): папка раскрывается
  столбиком с шапкой, сервер внутри выбирается, сайдбар — группы
  ролей с цветами (АДМИН/МОДЕРАТОР/РАЗРАБОТЧИК/БОТ/ОФЛАЙН), статусы и
  активности, артефактов нет.

## [0.9.2] — 2026-10-15

Окончательное закрытие close 4002 (v0.9.1 всё ещё слала до 25 каналов
в одном op 37 — живой шлюз держит максимум 5) и настоящий ленивый
сайдбар участников: `GUILD_MEMBER_LIST_UPDATE` с серверной сборкой
групп и пресенсов, 1:1 с официальным клиентом.

### Fixed
- **close 4002 «Error while decoding payload» — финальная часть**:
  v0.9.1 клала member-диапазоны до 25 каналов в один op 37 —
  живой юзер-шлюз закрывает соединение на большем числе. В бандле
  discord.com подписки каналов живут в LRU-кэше максимум из 5
  (`ChannelsStore new LRU({max: 5})`). Теперь протокол 1:1:
  `subscribe_guild` = op 37 БЕЗ каналов (пресенсы/typing/threads/
  member_updates; на него же приезжает GUILD_CREATE), а ленивый
  список — отдельный `subscribe_channel` с ОДНИМ каналом и
  диапазоном `[[0, 99]]`, ровно как `subscribeChannel` официала,
  на КАЖДОЕ переключение канала (без дедупа — свежий SYNC и есть
  самовосстановление). `channel_id = null` → псевдоканал «0»
  (общий список гильдии).
- **4002 на команды до READY**: op 37, отправленный до первого
  DISPATCH (клик по серверу во время переподключения), браковался
  шлюзом. Команды теперь буферизуются и выливаются после READY —
  как CONNECTION_OPEN → flush подписок в официальном клиенте.
- **Подписки после переподключения**: сервер держит подписки op 37
  только в рамках соединения. READY и RESUMED переигрывают подписки
  каналов из кэша (`member_lists` хранит guild→channel), фронтенд
  параллельно переигрывает выбор гильдии — как flush на
  CONNECTION_OPEN/CONNECTION_RESUMED у официала.

### Added
- **Ленивый сайдбар участников** (`GUILD_MEMBER_LIST_UPDATE`):
  сервер присылает ГОТОВЫЙ сайдбар — заголовки групп («В сети»,
  роли, «Оффлайн») и участников вперемешку, в финальном порядке, с
  пресенсами и активностями. Применяются инкрементальные ops
  SYNC/INSERT/UPDATE/DELETE/INVALIDATE (с клампами индексов),
  снапшот уезжает в UI. Цвет ника — по высшей цветной роли,
  подпись — кастомный статус или игра; клик/правый клик —
  профиль-карточка. Фолбэк на старый union-список — для
  бот-аккаунтов (op 8) и мгновения до первого SYNC.
- Гидратация кэшей из member-list ops: статусы и карточки
  участников, приехавшие ленивым списком, видят профиль-карточка,
  ЛС и «кто в сети» (то, что в официале делают UserStore /
  PresenceStore из этих же ops).

### Verified
- `cargo check`/`clippy --all-targets -D warnings` (обычный +
  audio) — чисто; cargo fmt — ок; svelte-check — 0 ошибок;
  vite build — ок.
- Применение ops ленивого списка: 9 тестов в scripts/logic-test
  (SYNC-замена, INSERT/UPDATE/DELETE по индексу, клампы
  вне-диапазонных индексов, INVALIDATE с энд-инклюзивом, no-op
  ренджи, повторный SYNC) — PASS.

## [0.9.1] — 2026-10-15

Критичный протокольный фикс (шлюз падал close 4002 посреди загрузки
серверов — из-за этого «не все сервера», «не видно кто в сети» и
«иконки через раз»), папки серверов, новый иконный набор, Quick
Switcher и красные бейджи упоминаний.

### Fixed
- **close 4002 «Error while decoding payload»** — корень всех трёх
  главных жалоб: op 14 (ленивый список участников) живой юзер-шлюз
  больше не принимает. Сверено с бандлом официального клиента:
  member-диапазоны каналов (`{cid: [[0,99]]}`) едут ВНУТРИ op 37
  (`GUILD_SUBSCRIPTIONS_BULK`), op 14 официальный клиент не
  использует вовсе. Теперь подписка на гильдию = один op 37 c
  `channels`; из-за краша сессия перезапускалась до IDENTIFY,
  GUILD_CREATE-поток обрывался на середине, пресенсы и чанки
  участников терялись. Заодно: bulk-подписки чанкуются по 15 360 байт
  на кадр — точно как `updateGuildSubscriptions` официального клиента.
- **Deadlock подписки «стабов»**: гильдии из REST-union (без каналов
  в кэше) подписывались «в никуда» — ранний return не отправлял
  ничего и не давал GUILD_CREATE приехать. Теперь уходит «голая»
  подписка, а пометка «выполнено» ставится только на подписку с
  каналами.
- Иконки серверов «через раз» — следствие 4002-разрывов (свежие
  стабы перезаливались пустыми): после фикса поток GUILD_CREATE
  стабилен, иконки не мигают. Фолбэк на цветные инициалы при
  битом CDN-хэше сохранён.

### Added
- **Папки серверов** 📁 — как в оригинале: раскладка рейла
  декодируется из пользовательских настроек. Поддержаны оба формата:
  современный protobuf `user_settings_proto` (ручной минимальный
  декодер PreloadedUserSettings → GuildFolders, схема свёрена с
  бандлом discord.com) и legacy-JSON `guild_folders`. Папка —
  кружок с мини-иконками серверов (до 4 + «+N»), цвет папки,
  раскрытие в поповер со списком серверов; порядок «папки вперемешку
  с отдельными серверами» сохранён из настроек (rail_order).
  Обновления настроек (USER_SETTINGS_PROTO_UPDATE) подхватываются
  на лету.
- **Quick Switcher** ⌨️ (Ctrl+K / Cmd+K) — мгновенный прыжок в любой
  канал, ЛС или сервер: Sublime-подобный матчинг (префикс > старт
  слова > подстрока), стрелки/Enter/Esc, показ «в каком сервере»
  для каналов. Первая «фишечка» от личного бренда RustyCord.
- **Красные бейджи упоминаний** 🔴 на серверах, папках и кнопке ЛС
  (счётчик непрочитанных @-упоминаний и @everyone), белая точка
  для обычных непрочитанных — как в оригинале.
- Новый иконный набор: **Tabler Icons** (MIT) вместо самодельных
  глифов — цельный stroke-стиль 24×24, 44 иконки инлайн (без
  внешних запросов). Все иконки приложения теперь единообразны.

### Verified
- `cargo check`/`clippy -D warnings` (обычный + audio) — чисто;
  svelte-check — 0 ошибок; vite build — ок.
- Декодер protobuf-настроек: юнит-тесты (packed/unpacked guild_ids,
  wrappers StringValue/UInt64Value/Int32Value, unknown-поля, битый
  base64) + живой прогон в scripts/logic-test — PASS.
- Визуальная проверка демо-режима (VLM): иконки единообразны,
  вёрстка без артефактов.

## [0.9.0] — 2026-10-15

Production-polish по живому фидбеку после первого реального входа:
сервера/иконки, звонки в ЛС, онлайн-состав, скрытые каналы, демо-режим
убран из собранного приложения.

### Added
- **Звонки в ЛС и группах** 📞 — op 4 с `guild_id: null` (протокол
  DM-звонков Discord): голосовой сервер идентифицирует сессию по
  channel_id, он же уходит songbird'у как `server_id`. Кнопка звонка
  в шапке беседы, колл-бар с участниками/мьютами/сбросом, баннер
  «Идёт звонок — Присоединиться», если собеседник уже звонит,
  голосовая панель в сайдбаре беседы. VOICE_STATE_UPDATE с
  `guild_id: null` больше не выбрасывается из потока событий —
  участники звонка видны всем.
- **Скрытые каналы** 🔒 — модель канала несёт `permission_overwrites`
  (allow/deny строкой и числом), UI считает VIEW_CHANNEL по алгоритму
  Discord (@everyone → роли → личные перезаписи, ADMINISTRATOR
  short-circuit) и прячет недоступные каналы и опустевшие категории.
  Автовыбор канала при входе на сервер тоже выбирает только из
  видимых. Без данных о ролях ничего не прячем — «лучше показать
  лишний канал, чем спрятать весь сервер».
- Статусы собеседников ЛС/групп берутся из всех источников (друзья →
  любые общие серверы) — партнёры по группе больше не «вечно офлайн».

### Fixed
- **Все сервера аккаунта + их иконки**: `GET /users/@me/guilds
  ?limit=200` теперь не только освежает имена/иконки, но и ДОБАВЛЯЕТ
  гильдии, отсутствующие в READY-стабах (union) — раньше часть
  серверов не отображалась вовсе, а иконки не подгружались. Новые
  гильдии сразу подписываются (op 37) — GUILD_CREATE подвезёт каналы.
  У битых иконок (устаревший хэш) — фолбэк на цветные инициалы.
- **Список «кто в сети»**: строки строятся из объединения карточек
  участников и пресенсов (merged_presences/op 14 дают статусы людей,
  чья карточка ещё не приехала — как в оригинале); подписка op 14
  расширена с 10 до 25 каналов; счётчик «В сети — N · всего M»;
  офлайн-список с потолком 100 («…и ещё N») вместо бесконечного.
- Демо-режим спрятан в собранном приложении (кнопка есть только при
  разработке в браузере) — production-клиент выглядит как клиент.

### Verified
- `cargo clippy --all-targets` (оба режима) и `svelte-check` — чисто.

Хотфикс QR-входа: v0.3.0 реализовывала устаревшую (v1) схему remote-auth,

### Fixed
- **QR-вход переписан на актуальный протокол v2** (по документации

**Ядро (Rust, src-tauri)**
- Gateway-клиент Discord (WebSocket): рукопожатие HELLO → IDENTIFY/RESUME,
  heartbeat ~41.25 с с детектом «зомби»-соединения по отсутствию HEARTBEAT_ACK,
  реконнект с экспоненциальным бэкоффом 1→30 с, обработка close-кодов
  (4004 — невалидный токен, 4014 — деградация интентов, 1000 — чистый реконнект).
- Кэш состояния: гильдии, каналы, участники, роли, сообщения, presence,
  voice states — за `RwLock` без блокировки UI-потока.
- REST-клиент с полными rate-limit-бакетами: парсинг `X-RateLimit-*` заголовков,
  маршрутные ключи с мажорными ID, 429-backoff, глобальный lock на `X-RateLimit-Global`.
- Голосовые каналы: полный сигналинг Voice v4 (WS HELLO → IDENTIFY → READY с SSRC →
  UDP IP discovery для NAT-проброса → SELECT_PROTOCOL → SESSION_DESCRIPTION),
  парсер RTP, шифрование xsalsa20poly1305 (nonce = RTP-заголовок, tag-first layout),
  маппинг SSRC → user через опкоды 12/13.
- Декодер Snowflake-ID (время создания, worker/process/increment) с тестами.
- 15 Tauri-команд: логин, гильдии/каналы/сообщения, голос, kick/ban, роли.

**Интерфейс (Svelte 5, runes)**
- Пиксельная тематика Discord: #313338 / #5865F2, шрифты gg sans-подобные,
  все 15 компонентов — от ServerRail до VoiceView.
- Живые обновления через 25+ Gateway-событий: сообщения, реакции, typing,
  presence, speaking-индикаторы.
- Демо-режим для браузера без Discord-токена (MockBackend эмулирует Gateway).
- Инспектор Snowflake, контекстные меню, профили с ролями и правами.
- Консоль протокола: отправка сырых JSON-кадров прямо в Gateway websocket
  (команда `gateway_send_raw` + вкладка «Протокол» в настройках) — инструмент
  протокольных экспериментов как у настоящего клиента.
- Полный набор иконок приложения: PNG (32…512) + многослойный ICO + ICNS,
  логотип «шестерёнка в облачке чата» на блурпле-градиенте Discord.

**Инфраструктура**
- Репозиторий проверен реальной компиляцией: `cargo check` + `cargo clippy --all-targets
  -D warnings` по всему дереву зависимостей Tauri 2, unit-тесты crypto (roundtrip/
  tamper/wrong-key) и snowflake проходят.
- CI: svelte-check + production-сборка фронтенда, cargo fmt/clippy/test
  на трёх платформах (`.github/workflows/ci.yml`).
- Dev-сборка установщиков на каждый пуш в main (`.github/workflows/dev-build.yml`).
- Релизы по тегу v*: проверка консистентности версий, сборка macOS (universal),
  Linux (deb/rpm/AppImage), Windows (NSIS/MSI), черновик GitHub Release
  (`.github/workflows/release.yml`).
- Dependabot (npm + cargo + actions), шаблоны issue/PR, .editorconfig, CHANGELOG.
