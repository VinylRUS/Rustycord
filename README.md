> ⚠️ **Прочитайте перед запуском.** RustyCord работает на **пользовательском токене** (как Vencord/Vesktop), а это формально противоречит правилам Discord. Мы не знаем, как Discord отреагирует на конкретный аккаунт, поэтому используйте клиент на свой риск. Мы **не помогаем** с селфботами, спамом, автоматизацией от имени аккаунта и обходом защиты Discord, и этому проекту такие вещи не нужны. Подробности в [FAQ](#-faq).

## 💡 Зачем это

Всё началось с того, что официальный клиент Discord доел почти 3 ГБ оперативки. Я увидел, как люди пересобирают пакеты Adobe и Microsoft Office на Rust с помощью нейросетей, и подумал: «чем я хуже?»

Сначала появился RustyCord на Tauri: клиент без Electron, который стартует и живёт в разы легче. А в v0.11 весь протокол переехал в отдельное ядро `rustycord-core`, и поверх него вырос второй, **полностью нативный** фронтенд на GPUI — тот самый движок, на котором написан редактор Zed. Один бинарник на несколько мегабайт, мгновенный старт, вообще никакого вебдвижка. С v0.12.0 GPUI-версия — основной клиент, а Tauri-версия переведена в legacy: её исходники остаются в репозитории, и установленная копия сама предлагает обновиться на новую.

Но у проекта есть цель и интереснее лёгкости: **добавить то, что Discord мог бы сделать сам, но почему-то не делает.** Не инструменты для нарушений, а обычное удобство: чтобы пользоваться этим клиентом было не мерзко.

## 📊 Цифры

| | GPUI (основной) | Tauri (legacy) | Официальный Discord |
|---|---|---|---|
| Размер | бинарник **5–9 МБ** | установщик 4–12 МБ (AppImage — 93 МБ, тащит всё с собой) | сотни мегабайт |
| Оперативная память | нативное приложение без вебдвижка — **ждём ваших замеров** | **~83 МБ** в пике¹ | **~500 МБ** сразу после запуска |

¹ Замер автора: Windows 11, Диспетчер задач, все процессы WebView2 + ядро, пик при переходах по крупным серверам. Размеры — по релизным архивам v0.11.0. Одна машина, не лабораторный бенчмарк. Если у вас получилось иначе, присылайте цифры в issues, нам важно знать.

## 🏗 Ядро, основной клиент и legacy-версия

Cargo workspace из трёх частей:

- **`crates/rustycord-core`** — весь Discord-протокол без UI-зависимостей: Gateway (WebSocket), REST, голос (songbird + cpal), remote-auth для QR-входа и отпечаток клиента 1:1 с официальным (X-Super-Properties, IDENTIFY). Контракт с UI — два трейта: `EventSink` (события) и `CaptchaSolver` (капча).
- **`app-gpui`** — основной клиент на GPUI 0.2: один бинарник, IME-ввод (русский работает), нативные файловые диалоги, установщики для всех платформ. Ему больше всего нужны тестеры.
- **`src-tauri`** — **legacy**-версия на Tauri 2 + Svelte 5: системный WebView вместо Chromium, треды/форумы и JS-плагины. С 0.12.0 в релизы не собирается, установленная копия автоматически мигрирует на GPUI.

## 🚀 Запуск

### Готовые сборки

На странице [Releases](https://github.com/VinylRUS/Rustycord/releases) — сборки GPUI-клиента:

- **установщики:** `RustyCord_<v>_x64-setup.exe` (Windows, NSIS — как у прежней Tauri-версии), `RustyCord_<v>_universal.dmg` (macOS, Apple Silicon + Intel), `RustyCord_<v>_amd64.AppImage` и `rustycord_<v>_amd64.deb` (Linux);
- **портативные архивы:** `rustycord-gpui-windows-x64.zip`, `rustycord-gpui-linux-x64.tar.gz`, `rustycord-gpui-macos-universal.tar.gz` — просто бинарник без установки.

Установленная ранее Tauri-версия при проверке обновлений сама предложит перейти на GPUI («Обновить автоматически»): установщик встанет на прежнее место, ярлыки и записи в «Программах и компонентах» сохранятся. Пользователям deb/rpm на Linux нужно поставить новый `.deb`/`.AppImage` вручную. Последние инсталляторы Tauri-версии — в релизах ≤ 0.11.0.

### Из исходников

Нужен [Rust](https://rustup.rs) ≥ 1.82.

**GPUI-версия** (нативная):

```bash
git clone https://github.com/VinylRUS/Rustycord.git && cd Rustycord
cargo run -p rustycord-gpui --release
```

Linux-зависимости (webkit нужен только для окна капчи и превью): `sudo apt install libwebkit2gtk-4.1-dev libasound2-dev libopus-dev cmake libfontconfig1-dev libxcb1-dev libxkbcommon-dev libxkbcommon-x11-dev`.
Без системных библиотек код всё равно проверяется: `cargo check -p rustycord-gpui --no-default-features` (headless-режим, как в CI).

**Tauri-версия** (нужен ещё [Node.js](https://nodejs.org) ≥ 20 и системные библиотеки Tauri, [список для вашей ОС](CONTRIBUTING.md#как-собрать-и-запустить)):

```bash
npm install
npm run tauri dev      # откроет окно приложения
```

Демо Tauri-версии без входа в аккаунт: `npm run dev` и откройте `http://localhost:1420`.

Подробные логи любой версии: `RUST_LOG=debug` (например, `RUST_LOG=debug cargo run -p rustycord-gpui`).

## 🛠 Что внутри

- **Ядро `rustycord-core`:** tokio, tokio-tungstenite (Gateway), reqwest (REST), songbird (голос), cpal (аудиоустройства); remote-auth, отпечаток клиента. Разбор протокола (Gateway, op 37, голос, remote-auth) — в подробных комментариях кода ядра: если вас тянет в реверс, стартовая точка там.
- **Нативный UI (`app-gpui`):** GPUI 0.2, IME-композер (EntityInputHandler), файловые диалоги rfd, окна капчи и превью на wry + winit; упаковка в установщики — `packaging/`.
- **Классический UI (`src-tauri`, legacy):** Tauri 2, Svelte 5 + TypeScript, системный WebView вместо Chromium; в релизы не собирается, обновляет пользователей на GPUI.
- **Плагины:** JS-файлы в духе Vencord для Tauri-версии (см. [`plugins/`](plugins)); в GPUI их функции сделаны нативными переключателями в настройках.

## 🔭 Куда идёт проект

Официальный клиент Discord тоже переходит на Rust — значит, идея была не такая уж бешеная. Наша ниша от этого не меняется: лёгкость, честность про состояние и удобство. Ближайшие планы:

- **Видео-тракт для Go Live и камеры** (захват → кодек → RTP по voice-UDP): сейчас обе версии умеют сигналинг и локальное превью, а вот доехать до зрителя картинка пока не может — это главная цель следующего мажорного релиза.
- **GPUI-версия: сохранение токена и настроек между запусками** (сейчас токен живёт только в памяти сессии), треды и форумы, встроенный авто-апдейтер (пока обновление — вручную установщиком с Releases).
- **QoL-функции, которых не хватает Discord:** закреплённые чаты поверх списка, единый список непрочитанного по всем серверам, свой порядок и группировка каналов, поиск по локальной истории. Мерило простое: функция улучшает жизнь человеку, а не делает что-то за него от имени аккаунта.
- **Панели ботов внутри клиента (концепт).** Бот публикует **декларативный манифест** (описание панелей и кнопок без исполняемого кода), клиент сам рисует интерфейс. Пока набросок — обсуждайте в [Discussions](https://github.com/VinylRUS/Rustycord/discussions).

## 🧭 Принципы проекта

1. Клиент создан, чтобы **улучшать** жизнь пользователей Discord, а не вредить сообществу.
2. Никаких селфботов, массовой рассылки, автоматизации от имени аккаунта и обхода защиты Discord. Просьбы о таком закрываются без обсуждения.

## ❓ FAQ

**Что качать?** GPUI-версию — с 0.12.0 это основной клиент (нативный, лёгкий, токен не остаётся на диске). Tauri-версия переведена в legacy: в релизы она больше не собирается, но установленная копия сама предложит обновиться на GPUI. Ставить legacy-версию имеет смысл, только если прямо сейчас нужны треды, форумы или JS-плагины — тогда соберите её из исходников или возьмите релиз ≤ 0.11.0.

**У меня стоит Tauri-версия — как переехать?** Ничего специально делать не надо: в карточке обновления нажмите «Обновить автоматически» — клиент скачает установщик GPUI-версии и поставит его на прежнее место (Windows/macOS/AppImage; для deb/rpm на Linux скачайте `.deb`/`.AppImage` из релиза вручную). После первого запуска войдите по QR-коду или токену заново: токен legacy-версии хранился в `localStorage` WebView и не переносится.

**Это законно?** Клиенты на пользовательском токене (Vencord, Vesktop и другие) существуют давно, но формально это против правил Discord. Баны за обычное использование редки, но возможны. Решение за вами.

**Безопасно ли вводить токен?** Токен уходит только на серверы Discord. Дальше — зависит от версии: **GPUI** держит его только в памяти и после закрытия на диске не остаётся ничего (поэтому вводится заново при каждом запуске); **Tauri** хранит в `localStorage` WebView. Перенос в системное хранилище (Keychain/Credential Manager/libsecret) — отличная задача для контрибьютора. Не вставляйте токен в чужие программы и не показывайте логи с токеном.

**Почему пользовательский токен, а не бот?** Потому что нужен полный клиентский опыт: серверы, ЛС, войс, а не только возможности бота. Режим бота при этом остался для отладки.

**Discord попросил капчу.** Это антифрод. RustyCord откроет отдельное окно подтверждения на discord.com, решите её там, и вход продолжится. Нюанс: в GPUI-версии на macOS окно капчи пока недоступно — там входите по токену или QR.

**Я включил Go Live, а меня никто не видит.** Известное ограничение: сигналинг, чипы трансляций и локальное превью работают, но сам видео-тракт до зрителя (захват → кодек → RTP) ещё в разработке — это главная цель следующего мажорного релиза. Честно пишем об этом в таблице выше.
